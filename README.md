# web_version — веб-версия игры «Киллер / Папарацци»

Сайт на FastAPI + Jinja2 (серверный рендер, без JavaScript). Вход — по одноразовой
«магической ссылке», которую выдаёт бот. Пока настоящих Telegram/VK-ботов нет, их
диалог **эмулируется страницей чата** (`/`), а игровой дашборд живёт на `/app`.

## Запуск

Проще всего — скриптом `start.sh` (Git Bash на Windows, либо Linux/macOS). Он сам создаёт
виртуальное окружение, ставит зависимости и поднимает сервер:

```bash
./start.sh              # http://127.0.0.1:8000
./start.sh 9000         # свой порт
HOST=0.0.0.0 ./start.sh # слушать всю сеть (доступ с других устройств)
```

Открыть в браузере: <http://127.0.0.1:8000>. Остановить — `Ctrl+C`.

<details>
<summary>Запуск вручную (без скрипта)</summary>

```bash
python -m pip install -r requirements.txt
python -m uvicorn app:app --reload
```

> Запускайте именно `python -m uvicorn ...`, а не голый `uvicorn`: скрипт `uvicorn.exe`
> ставится в `...\PythonXX\Scripts`, которого часто нет в PATH (тогда `uvicorn: command
> not found`). Через `python -m` PATH не нужен. То же самое с `python -m pip`.
</details>

## Как войти (эмуляция чата)

1. `/` — страница «бота». Введите **id** (username), например `parar020100` → откроется
   чат `/chat/<username>` (профиль создаётся при первом открытии).
2. В чате нажмите **/start** — «бот» выдаст **постоянную ссылку** для входа.
3. Переход по ссылке (`/login?token=…`) кладёт вход в подписанную cookie-сессию и
   открывает игровой дашборд `/app`. Выход — `/logout`.

### Разные пользователи в разных вкладках (отладка)
Обычная сессия хранится в **cookie**, а cookie в браузере одна на все вкладки — поэтому
без спец-режима во всех вкладках будет один и тот же пользователь. Для тестирования есть
**отладочный вход** `?user=<username|id>`: он важнее cookie и **не пишется в неё**, так что
каждая вкладка со своим `?user=` независима.

- В dev-режиме сам вход по ссылке (`/login?token=…`) сразу перекидывает на
  `/app?user=<username>` — то есть **каждая присланная ссылка, открытая в своей вкладке,
  привязывает эту вкладку к своему игроку**. Открывайте разные ссылки в разных вкладках —
  они не мешают друг другу.
- Либо: войдите за админа (`parar020100`), откройте **👥 Список пользователей** и нажмите
  **«открыть как ↗»** (или на карточке игрока — «🕶 Открыть как…»): игрок откроется в новой вкладке.
- Вручную: `/app?user=bob` (по username) или `/app?user=3` (по внутреннему id).

Режим включён, только пока используется небезопасный dev-`SECRET_KEY`; в проде он выключен
(управляется `ALLOW_DEV_LOGIN`, см. `config.py`) — тогда вход обычный, через cookie. Полностью
изолированные сессии по-прежнему дают **разные браузеры/приватные окна**.

### Магические ссылки — как они устроены
Одноразовых ссылок нет — используется одна **постоянная** ссылка на канал:
- токен — 256 бит случайности (`secrets.token_urlsafe`);
- **постоянная**: работает всегда, не сгорает и не имеет срока;
- в БД (`persistent_login`) хранится только **SHA-256-хеш**, сама ссылка показывается
  **один раз** при выдаче; повторный `/start` = перевыпуск (прежняя ссылка сразу
  отключается);
- ссылка привязана к **каналу (identity), а не к пользователю**: если у человека есть и
  Telegram, и VK, у каждого канала своя независимая постоянная ссылка. Подробности — в
  `core/auth.py`.

**Админ:** пользователь с username `parar020100` при создании автоматически получает
права администратора (набор `DEFAULT_ADMINS` в `core/user.py`).

## Структура

```
killer_game_web/
├── start.sh             # запуск в один клик (venv + зависимости + uvicorn)
├── app.py               # FastAPI: маршруты (чат, вход, дашборд, действия)
├── config.template.py   # шаблон настроек (в git); копируется в config.py
├── config.py            # локальные настройки (в .gitignore, аналог config.py бота)
├── db.py                # SQLite: соединение (WAL), схема, init/drop
├── core/
│   ├── game.py          # модель игры (состояние, счётчики)
│   ├── user.py          # профиль/игровое состояние + DEFAULT_ADMINS
│   ├── identity.py      # канал связи профиля: tg / vk (+ доставка)
│   ├── auth.py          # одноразовые токены входа (magic-link)
│   ├── chat.py          # эмуляция переписки бот↔пользователь (data/chats/)
│   ├── msgfile.py       # общий формат журнала сообщений в текстовом файле
│   └── admin_log.py     # общий журнал админов (data/admin_log.txt)
├── data/                # БД + chats/ + admin_log.txt (в .gitignore)
├── templates/
│   ├── chat_entry.html  # страница входа в чат (поле id)
│   ├── chat.html        # переписка с ботом (история + /start)
│   ├── index.html       # игровой дашборд (light/dark)
│   └── admin_log.html   # страница общего журнала администраторов
├── requirements.txt
├── CONCEPT.md           # концепция и целевая архитектура
└── FEATURES.md          # инвентаризация всех фич бота — спецификация для порта
```

Состояние игры, игроки и их каналы хранятся в `data/killer_game.db` и переживают
перезапуск (`db.drop_db()` сбрасывает БД, чаты и журнал админов).

## Что дальше (по плану)

1. Подключить игровое ядро (`core/game.py`, `core/user.py`) вместо захардкоженных данных.
2. Вход по «магической ссылке» из бота (сессия-cookie).
3. Живые действия: узнать цель, сообщить о поимке (загрузка фото), accept/deny, админка.
4. Боты TG/VK — только уведомления + выдача ссылки для входа.
