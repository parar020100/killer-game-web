# web_version — веб-версия игры «Киллер / Папарацци»

Стартовый каркас сайта (FastAPI + Jinja2). Сейчас это **динамический макет** главного
экрана: Python (`app.py`) формирует текст статуса и набор кнопок — как в исходном боте —
и отдаёт их в шаблон `templates/index.html`. Данные пока захардкожены; БД и реальная
игровая логика подключатся на следующих шагах (см. общий план в
`../../.claude/plans/` и `PLAN.md` в корне репозитория).

## Запуск

Проще всего — скриптом `start.sh` (Git Bash на Windows, либо Linux/macOS). Он сам создаёт
виртуальное окружение, ставит зависимости и поднимает сервер:

```bash
./start.sh              # http://127.0.0.1:8000
./start.sh 9000         # свой порт
HOST=0.0.0.0 ./start.sh # слушать всю сеть (доступ с других устройств)
```

Открыть в браузере: <http://127.0.0.1:8000>. Остановить — `Ctrl+C`.

<details>
<summary>Запуск вручную (без скрипта)</summary>

```bash
python -m pip install -r requirements.txt
python -m uvicorn app:app --reload
```

> Запускайте именно `python -m uvicorn ...`, а не голый `uvicorn`: скрипт `uvicorn.exe`
> ставится в `...\PythonXX\Scripts`, которого часто нет в PATH (тогда `uvicorn: command
> not found`). Через `python -m` PATH не нужен. То же самое с `python -m pip`.
</details>

- `/` или `/?role=player` — меню игрока
- `/?role=admin` — меню админа

Переключатель ролей вверху страницы — это обычные ссылки: страницу каждый раз
рендерит Python (серверный рендер), а не JavaScript.

## Структура

```
killer_game_web/
├── start.sh             # запуск в один клик (venv + зависимости + uvicorn)
├── app.py               # FastAPI: маршруты + сборка экранов (player_view / admin_view)
├── db.py                # SQLite: соединение (WAL), схема, init/drop
├── core/
│   ├── game.py          # модель игры (состояние, счётчики)
│   ├── user.py          # модель пользователя (id с 1, профиль, регистрация)
│   ├── identity.py      # канал связи профиля: tg / vk / test (+ доставка)
│   └── inbox.py         # «входящие» тестовых идентичностей (файлы data/inboxes/)
├── data/                # БД killer_game.db + inboxes/ (в .gitignore)
├── templates/
│   ├── index.html       # Jinja2-шаблон главного экрана (light/dark)
│   └── inbox.html       # страница «входящих» тестовой идентичности
├── requirements.txt
├── CONCEPT.md           # концепция и целевая архитектура
└── FEATURES.md          # инвентаризация всех фич бота — спецификация для порта
```

## DEV-режим: тестовые пользователи и их «входящие»

Входа по аккаунту ещё нет. Текущий пользователь выбирается параметром `?as=<N>`
(по умолчанию 1) — каждое N это отдельная **тестовая идентичность** (`platform='test'`)
со своим профилем в БД. Реальные аккаунты Telegram/VK не нужны: в разных вкладках можно
открыть разных пользователей и, например, зарегистрировать нескольких:

- `/?role=admin&as=1` — админ открывает регистрацию / запускает игру
- `/?role=player&as=2`, `/?role=player&as=3` — разные игроки регистрируются

**Уведомления вместо бота.** Тестовый канал не шлёт сообщения в мессенджер, а
складывает их в текстовый файл `data/inboxes/test-<N>.txt`. Те же сообщения видно на
странице **`/inbox/<N>`** (ссылка «📨 входящие» в DEV-панели) — так проверяются рассылки
и личные уведомления, не заводя десяток аккаунтов. Профили `tg`/`vk` устроены так же,
но их доставка пока заглушена (лог в консоль) до подключения реальных ботов.

Состояние игры, игроки и их каналы хранятся в `data/killer_game.db` и переживают
перезапуск (`db.drop_db()` сбрасывает и БД, и тестовые «входящие»).
